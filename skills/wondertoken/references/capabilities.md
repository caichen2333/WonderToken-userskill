# 图片能力发现与条件执行

宿主品牌不代表当前会话能力。按实际任务分别检查：原生图片生成工具、可延迟发现的工具、已安装或已暴露的图片生成/编辑 Skill。只读取匹配 Skill，核对其底层工具、授权/配置和输出限制；存在 Skill 文件不能证明工具可用，能看图不能证明能生图。

照片定制要求读图和参考图生成；纪念图要求支持服务端返回的全部参考图、构图/输出约束，并能将真实输出保存为可上传文件。先使用宿主提供的工具/Skill 清单；清单不完整时，使用该宿主的工具发现接口、Skill 目录或官方支持的扩展查找方式，不盲目遍历其他 Agent 的私有目录。不得因为没看见名为 imagegen 的工具就跳过其他可用生图工具。

| 发现结果 | 行为 |
| --- | --- |
| 可用 | 按实际工具或 Skill 的用法执行；不擅自改选付费服务 |
| 确认不支持 | 已完成宿主允许的工具与 Skill 发现仍无可用方式；跳过生图，reason 为 unsupported |
| 暂不可用 | 找到工具但缺授权、缺配置或不能满足参考图/文件输出要求；说明实际原因，reason 为 unavailable |
| 尚未确认 | 清单不可见或发现步骤未完成；继续发现，必要时简短询问已配置的图片工具，同时完成无依赖的文字步骤；不能宣称“不支持” |

不要为了测试能力付费生成无关图片。不要自动安装其他 Skill、插件或开通图片服务。若用户明确提供了配置授权，按其授权完成准备后重新检查能力。会话内可复用结果；切换 Agent、增加工具或配置变化后必须重新发现，不能把无图能力存成永久玩家属性。

无可用生图能力时，领养直接使用已有六个官方形象并跳过照片定制。归家完成文字来信、费用结算与 Soul 整理后，调用 `record_memory_image_outcome` 记录本次跳过原因；只有已完成旅行可调用。实际生成/上传失败则分别记录 generation-failed / upload-failed。每次新状态变更生成 operationId，重试复用原参数和 ID。

确认不支持的提示示例：“当前 Agent 没有可用的图片生成能力，这次跳过纪念图；旅行来信、结算和回忆都已保存 📮。”若是工具缺授权、参考图不可用或生成失败，就说对应事实，不能套用“不支持”。

图片步骤不得阻塞或回滚文字、成长、钱包、Soul 和归档；仍按归家接口要求提交文字 imageBrief。记录跳过失败时诚实说明记录尚未成功，不重写旅行。之后照常询问是否匿名分享该趟轨迹；无纪念图也可使用固定宠物形象与真实路线参与偶遇。已有纪念图不重生成，不自动补历史图片。
