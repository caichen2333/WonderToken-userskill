# 安装后引导与使用说明

## 首次准备

支持 macOS、Linux、Windows，使用 Node.js 24.14+（24 LTS）与 npm。Windows 不要求 WSL；不使用 sudo 或修改系统执行策略。Node 缺失时指导用户从 https://nodejs.org/en/download 安装当前平台的 Node 24 LTS，并重新打开终端/Agent；安装新运行时需得到用户同意，已获授权不重复询问。

用当前 Skill 的真实绝对路径运行：

```text
node "<absolute-skill-root>/scripts/setup.mjs" doctor
```

该检查会准备共享身份并读取公开游戏配置，不领养、不出发、不结算 Token。检查连接、Node/SQLite、客户端依赖、Tokscale 准备情况；不会从 shell 猜测图片能力。图片能力必须由 Agent 按 capabilities.md 主动发现。

服务默认使用分发包配置的正式地址，普通玩家只需说“开始玩途”，检查和连接由 Agent 执行。当前配置缺失时，说明需要正式服务地址或用户自托管地址，不能把示例地址当作真实服务。自托管或切换服务可执行：

```text
node "<absolute-skill-root>/scripts/setup.mjs" configure --url "<真实 MCP URL>"
```

连接优先级：显式地址 → WONDERTOKEN_MCP_URL 环境变量 → 用户配置 → 分发默认值。云端要求 HTTPS，本机可用 http://127.0.0.1:8787/mcp。地址切换不会复制旧服务的宠物数据；升级保留用户配置。

## 工具调用

所有 Agent（包括 Codex）都通过随包客户端调用。无需安装或配置宿主 MCP，不使用已注册的 WonderToken 原生工具；下面所有业务工具均通过 `client.mjs call` 执行。

```text
node "<absolute-skill-root>/scripts/client.mjs" tools
node "<absolute-skill-root>/scripts/client.mjs" call get_game_state
```

call 的业务参数 JSON 从标准输入传入，空参数可输入 `{}`。客户端自行读取 playerKey，不把密钥放到命令参数、聊天或可分享配置里。需要 operationId 的操作由 Agent 生成 UUID；重试用原 ID 和原参数。

完整安装器会安装锁定的客户端依赖。手动复制 Skill 或通过插件安装后，doctor 的 `clientReady: false` 与 `clientRecovery` 会给出补齐命令。Agent 在已有安装授权范围内直接执行，再重跑 doctor；无需让用户自己操作或重复确认。只有宿主权限机制阻止下载/写入时，说明具体原因并请求必要权限：

```text
npm ci --prefix "<absolute-skill-root>" --omit=dev --ignore-scripts --no-audit --no-fund
```

这不安装 Tokscale，也不创建后台进程。补齐失败时说明原因并停止在线操作，不能切换到宿主原生 MCP 绕过问题。CLI 业务失败按结构化 error.recovery 处理，不因为报错改用其他身份或另一个服务。

## 给首次玩家的简短卡片

根据真实检查结果说明：“旅行信箱已接通 / 尚未接通”“图片可用 / 尚在检查 / 本次无法生成”“结算时采集本机各 Agent 可访问的历史已消耗 Token，与你在哪个 Agent 玩无关”。说明它只会结算尚未结算的历史使用增量，不会转移当前 Token 余额。随后提示“可以说：带我的宠物去旅行。首次旅行免费，不必先安装 Tokscale。”

无图时告诉玩家可选六个官方形象，并跳过照片定制；归家仍有旅行来信、结算和 Soul 回忆，也可主动分享匿名轨迹。别在每次互动重复检查说明，只在首次或配置/能力变化时主动展示。

首次免费旅行每现实 10 秒为一个旅行日，后续新旅程每现实 1 分钟为一个旅行日；具体配置以服务返回为准。已经出发的旅程保留出发时的节奏。主动询问进展可能扣除虚拟玩途币，预计归家日或第 28 日查询会直接归家。出发当下不扣币、不立即编故事。

## 共享身份、离线、升级与卸载

同一机器同一系统用户的 Agent 共用 `~/.wondertoken/player.json`、配置和 `offline.sqlite`（Windows 在用户主目录下）。不要把状态放进每个 Agent 的安装目录。不同系统用户与设备不自动合并；身份文件就是匿名账号，删除后无法找回旧宠物。不建议手动复制、编辑或轮换密钥。

已有有效离线许可且真实断网时可本地继续；所有离线记录标注“待旅行信箱确认”，不能离线发币、生图上传、整理 Soul 或分享。下一次互动先同步。共享锁冲突时稍后用原请求重试，不创建第二个账号或另一个离线数据库。

重复运行同一安装命令升级，保留身份和自托管地址。卸载只移除 Skill，不删除用户状态；手动安装的目录需按当前宿主的卸载方式移除。

## 常见问题

- Skill 安装完成但未出现：按当前宿主的技能激活/重载方法处理；必要时新开会话，并明确加载 SKILL.md。不要猜测所有 Agent 有同一种命令。
- 连接失败：检查 doctor 返回的真实地址及结构化错误。`LOCAL_PERMISSION_DENIED`、`EPERM`、`EACCES` 表示本机权限阻止执行或连接，不能据此宣称服务宕机或进入离线旅行；通过宿主正式权限机制申请同一命令所需权限，获准后重试。不关闭沙箱或修改全局安全配置。只有 `fetch failed` 而无原因时也不能直接断言服务故障，应检查底层网络错误或通过获准的健康检查核实。`PLAYER_NOT_FOUND` 是首次领养状态，服务已经响应。没有真实服务地址时先补配置；只有满足 Skill 定义的网络故障才使用离线许可。
- 运行时缺失：安装 Node 24 LTS 并重新打开宿主，检查 node 与 npm 都在其 PATH 中；不能用“Tokscale 可运行”替代 SQLite 检查。
- 无用量：先在相关 Agent 产生实际用量，再按固定版本 Tokscale 文档检查来源路径/同步条件。未发现不等于零用量。
- 发币为零：可能是重复采集或累计数据低于已结算最高值。按服务结果解释，不能改快照数字。
- 生图工具缺失/无授权：继续主动发现工具和相关 Skill；确定原因后跳过并告知，六个官方形象仍可游玩。
