# 旧旅行兼容流程

仅当服务不支持 progress-run-v1 或旅行不是 v3 时使用。

1. 将真实用户请求写入 source.json（kind=user-progress、text=用户原话，可附 messageRef），运行 `progress-workflow.mjs query --source source.json`，只使用它返回的窗口、位置、余额、返程估算、连续性、必经站、指令和 Soul 倾向。`soulContext` 只能影响感受与普通选择，不能创造事实或越过安全、预算、玩家指令和服务端路线。
2. `status: "home"` 或 `next: "deliver"` 时直接返回已保存状态；已归家不重新出发。`progressAvailable: false`，只反馈已旅行时长、已有来信和同行数（字段存在时）；不锁事实或写故事。没有新增时间才说“刚寄出上一封信”。
3. 准备后先给一条短进度，只可使用已报告的位置、阶段、已过去时间、路线名和同行数。无用户明确目的地时优先选择未去城市，同一地级市累计停留最多 10 个旅行日；然后确定已过去窗口内的移动、地标、活动、费用和可选偶遇；城市级目的地一次去重后并行确认，不逐个串行搜索。
4. 在线且 `localNewsContext.allowed` 时，才按 [local-news.md](local-news.md) 最多检索一则已核验本地热点；无能力、超时或无合适新闻直接跳过。锁定后的新闻不重新检索。
5. 按 `session.next` 执行，`outcome: "homecoming"` 必须完成本次归家；已有来源自动沿用，不重问路线或账单。`phase: "prepared"` 时先运行 `progress-workflow.mjs draft`，再用 `progress-workflow.mjs lock`。活动用一个合法 category 和最多五个不重复 tags；移动最多二十段，城市仍最多五个。不得以清空移动、活动或费用来绕过校验。费用、停留时间和总额必须通过本地预检。`MUST_RETURN` 时放弃游玩方案，改为朴素返程。锁定成功后发一条 `📍 旅途剪影`，只取 2–4 个已锁定事实。
6. 只用锁定事实写一封 450–500 个中文字符、3–4 个非空段落的来信。用动作、气味、声音、小习惯和心情写活宠物；不增添未锁定的城市、事件或花费。普通小插曲只在本封自然收束，不写进 `openThreads`。经典偶遇说明人物和来源时空；匿名宠物偶遇只写两只宠物和已完成轨迹。新闻自然融入约 60–100 字，不能写成宠物亲历。
7. 用 `progress-workflow.mjs submit` 保存正文。只提交正文里实际使用的至多两条 Soul 回忆；失败或过期时不能说已存档或扣费。提交成功后直接复用已保存的正文，勿重写第二版。
